# 产品原型规范（product-prototype-rule）

一套用于生成可运行原型与可编辑设计稿的个人规范，默认先制作前端原型，再根据原型制作设计稿；供 AI 助手在用户明确要求按本规范生成/迭代产物时加载执行。

## 仓库结构

- `SKILL.md` — 规范正文（跨端通用）：交付模式选择、核心原则、工作流程、需求补全边界、页面状态、组件规范、交互流转、视觉优先级、验收与交付说明。
- `references/design-delivery.md` — 可编辑设计稿模式：原型转稿、jsDesign MCP 连接、画布制作、组件复用、状态表达、对照检查与源稿交付。
- `references/b-end.md` — B 端默认基准：承载与预览、布局基准、组件默认、交付说明（标注层）、状态演示入口。
- `references/c-end.md` — C 端默认基准（手机 / 平板 / App / 小程序）：承载与预览、工程结构、布局基准、组件默认、交付说明、状态演示入口。
- `references/design-tokens.md` — 默认设计 token（基于 Arco Design 风格）：颜色、字号、间距、圆角阴影、现代视觉规范；视觉优先级见 `SKILL.md` 的「设计 token」节。

## 快速使用

在支持 Skill 的 AI 助手（如 WorkBuddy）中说「按产品原型规范生成一个××页面/原型」即可触发。

例如：

- 「按产品原型规范做一个 B 端接种工作台，先出前端原型，再根据原型制作设计稿。」
- 「按产品原型规范，这次只做平板端接种登记的前端原型。」
- 「按产品原型规范，根据现有原型，用 jsDesign MCP 制作可编辑设计稿。」

模式选择见 `SKILL.md` 的「交付模式」节。维护规范不需要连接设计插件；实际制作设计稿的连接前提见 `references/design-delivery.md`。

## 约定摘要

- 承载、技术栈与端基准按目标端区分：B 端见 `references/b-end.md`，C 端见 `references/c-end.md`；工程与运行要求仅用于可运行原型。
- 使用业务样例数据；需求补全、页面状态与流程规则见 `SKILL.md`，按所选模式表达和验收。
- 交付说明形式见 `SKILL.md` 的「交付说明」节；设计稿的画布说明与源稿交付见 `references/design-delivery.md`。
