# 可编辑设计稿交付（jsDesign MCP）

仅在选择设计稿模式时读取。目标端的布局与组件基准仍见对应端 reference；业务判断、视觉优先级与验收状态统一见 `../SKILL.md`。

## 根据原型转稿

- 默认作为前端原型完成后的第二阶段，执行顺序和仅交单一产物的例外见 `../SKILL.md` 的「交付模式」与「工作流程」。
- 记录本次来源原型的文件或工程位置、可识别版本（如版本标识或文件修改时间）、预览地址（如有）、目标尺寸及纳入范围的页面与状态，便于后续对照与迭代。
- 打开来源原型，查看实际渲染并操作相关流程，收集关键页面、弹窗及适用状态的截图，结合源码中的文字、样式与尺寸建立画板对应关系。无法预览时说明限制，不声称已验证视觉一致性。
- 多页面转稿时，先选一个能代表主要结构和控件的页面制作设计稿，按「验收与交付」节自查布局、字体、图层与组件可编辑性；修复问题后再展开其余页面，由 AI 自查推进，无需逐页等待用户确认。
- 按原型中的页面、字段、校验规则、文案、样例数据、状态及操作去向转稿；源原型的假设、待确认和未验证项一并保留，不能在设计稿中默认为已确认或已验证。
- 将原型中的标注开关、状态演示入口等工具位排除在产品界面之外，相关信息转入画布说明区域。
- 转稿的视觉依据统一见 `../SKILL.md` 的「设计 token」节；HTML 导入仅作为可选辅助方式，可编辑性要求见下节。

## 连接与目标

- 修改本规范不需要连接插件。实际制作时，需要在目标设计客户端运行 MCP 插件并保持连接；先用 `jsd_get_page` 读取当前页、资源清单，必要时用 `jsd_ping` 确认连接与平台能力。
- 根据用户指定或已明确的上下文确定目标文件、页面与修改范围；无法判断目标时询问，不把当前打开的文件视为任意修改的授权。
- 插件未连接时说明需要启动插件，可继续整理页面清单、原型截图与待确认项；已完成的原型正常交付，同时明确设计稿待完成，不宣称已创建设计稿，也不以图片替代源稿。

## 画布制作

- 优先复用资源清单中的组件、样式及可用变量。同一结构重复出现时使用组件和实例；缺少的资源再按当前工具支持的能力创建。
- 用原生文本、容器、图形及组件搭建可编辑页面；不把整屏截图或扁平矢量图作为可编辑源稿。HTML 导入可能丢失复杂样式，导入后须检查图层结构和视觉，不承诺自动还原。
- 按「页面 → 语义分区 → 组件 / 内容」组织图层，以用途命名，例如「接种工作台/筛选区」「按钮/主按钮」。容器适合时使用自动布局，字体从当前平台可用字体中选择。
- 按页面及状态命名画板，例如「接种工作台/默认」「接种工作台/空态」。新增画板放在明确的空闲区域，迭代时定位相关节点，避免覆盖或重建无关页面。
- 组件属性、变量、变体等能力以实际平台和工具返回为准；不支持变体时用独立状态组件或画板表达，不反复调用不支持的入口。

## 状态与流程

- 适用的空态、加载态、成功态、失败/异常态通过独立画板或明确命名的组件状态展示，并给出可定位的画板或节点。弹窗、校验错误和危险操作确认同样表达，避免只在文字里声称已覆盖。
- 在设计说明中关联「来源页面/状态 → 触发操作 → 目标页面/状态」，保持各状态中的样例数据及业务关系一致。
- 不默认承诺可点击跳转、动画或实时数据变化。用户要求此类交互时，先核对实际工具能力；能力不足时说明未实现，保留静态状态与操作说明，不能标记动态交互验收通过。

## 验收与交付

- 回读图层，检查结构、文字可编辑性、资源复用及状态完整性；逐项处理工具 warnings，不能仅以调用成功判断生效。
- 导出主要画板及发生变化的状态预览，实际查看排版、字体、遮挡、裁剪、溢出和状态一致性，修复发现的问题。未能导出或查看时，相关视觉项标记「未验证」。
- 根据原型转稿时，在相同目标尺寸下对照源原型截图和设计稿预览，检查布局、文字、字段、数据与状态画板；流程说明对应原型实际行为。用户要求的差异在说明中列明，其余不一致项修复，无法核实的项标记「未验证」。
- 在画布的独立说明区域记录页面用途、字段与校验规则、操作到目标状态的对应关系、假设和待确认项；关联具体画板，迭代时同步。说明不混入产品界面，不绘制无法使用的标注开关。
- 交付可编辑源稿的实际文件/页面定位信息，以及关键画板名称或节点 ID；能获取真实访问链接时提供链接，不编造链接。导出预览按需提供，不能替代源稿。
- 转稿交付说明关联来源原型版本与「原型页面/状态 → 设计画板/节点」的对应关系。迭代后更新映射；尚未同步的源原型变更明确标记待更新。
- 交付回复与验收状态沿用 `../SKILL.md`，明确静态设计表达和实际已配置的交互范围。
